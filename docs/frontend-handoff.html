TV Show Recommender — Hackathon Partner Handoff Document

For the designer/frontend dev: This document covers every screen, its components, data it consumes, and design notes. The backend (Supabase schema + Edge Functions) and scoring engine are handled separately. Your job is to build the screens and components listed here — the data contracts tell you exactly what shape the data will arrive in.

Auth Screens

Splash / Login /auth

Full-screen branded screen. App logo/name, tagline, two login buttons. No email/password — social only.

  • SocialLoginButtonAccepts provider: "google" | "apple", onPress. Shows provider logo + label.
  • AppLogoApp name + icon mark, centred on screen.

On successful login, check if profile + tasteProfile exist → route to Onboarding or Home.

Onboarding Flow

Onboarding Q&A /onboarding

8-step wizard. One question per screen with a progress bar. Answers accumulate in local state and are submitted as a single tasteProfile object on completion.

  • OnboardingProgressStep indicator, e.g. "3 of 8". Linear bar.
  • QuestionCardAccepts question: string, type: "multi-select" | "single-select", options: string[], onAnswer.
  • OptionChipSelectable pill. Selected state = filled. Used inside QuestionCard.
  • OnboardingNavBack + Next/Finish buttons. Next disabled until at least one option selected.

Home Screen

Home — Today's Recommendation /

Primary screen. Shows the user's current recommendation as a large card. If no recommendation exists yet, shows a placeholder state.

  • RecommendationCardLarge card. Props: showTitle, overview, posterUrl, genres[], network, year. Tap expands to detail.
  • RecommendationDetailBottom sheet or full screen. Same data + "Mark as Seen" button, "Challenge to RPS" button.
  • EmptyRecommendationPlaceholder shown before first rec is generated. "Your first pick is on its way" state.
  • NextPickCountdownSmall muted label showing time until next scheduled recommendation.

Data shape for RecommendationCard:

Map Screen

US Map View /map

Uses react-native-maps. Shows the US. Each unique zip code with at least one recommendation gets a pin. Tapping a pin shows a small callout with the show title and poster thumbnail.

  • RecommendationMapWraps MapView. Renders markers from pins[] prop.
  • ZipPinCustom marker. Props: zipCode, showTitle, posterUrl, count (how many users in that zip).
  • PinCalloutShown on marker tap. Show poster thumbnail + title + "N people".

Data shape for each pin:

FieldType
zipCodestring
latnumber (derived from zip centroid)
lngnumber
showTitlestring (most recommended in that zip today)
posterUrlstring
countnumber

Data fetched from Edge Function getRecommendationsNearZip. Initial map bounds = contiguous US.

Friends Screens

Friends Feed /friends

Scrollable list of accepted friends. Each row shows the friend's avatar, name, and their current recommendation. A "Promote" button sends them a push nudge.

  • FriendFeedItemRow component. Props: profile, recommendation, onPromote, onViewProfile.
  • PromoteButtonSmall action button. Shows confirmation toast on press. Disabled after promote sent (until next day).
  • PendingRequestsBannerShows at top if there are incoming friend requests. Tap to view list.
  • EmptyFriendsIllustrated empty state with "Add your first friend" CTA.
Add Friends /friends/add

Three ways to add a friend. Tabs or segmented control across the top.

  • UsernameSearchText input + search button. Returns UserSearchResult[]. Each result has avatar, name, "Add" button.
  • QRCodeDisplayShows the current user's QR code (value = their qr_code field, e.g. @ahmed). Uses react-native-qrcode-svg. Share button below.
  • QRScannerCamera view using expo-camera. Scans a friend's QR, resolves username, shows confirm sheet.
  • ShareLinkButtonTriggers native share sheet with a deep link tvrecc://add/@username.
Friend Profile /friends/[id]

Friend's avatar, display name, current recommendation card, and a "Challenge to RPS" button that deep-links into the RPS flow with this friend pre-selected.

Rock Paper Scissors Screens

Real-time note: All RPS screens after a match is created subscribe to a Supabase Realtime channel on rps_matches for their match ID. UI updates reactively — no manual refresh needed.
RPS Home /rps

Shows active/pending matches. "New Challenge" button starts the flow. Incoming challenges appear as cards with Accept/Decline.

  • ActiveMatchCardShows opponent name, status badge, expires countdown if pending.
  • IncomingChallengeCardOpponent name, their show pick, Accept / Decline buttons.
Pick Show /rps/pick-show

Two options: use today's recommendation (pre-filled card shown) or search TVDB. TVDB search is a text input that hits the TVDB /search endpoint and returns a list of shows.

  • TodaysRecOptionTappable card showing today's rec. Selected state = highlighted border.
  • TVDBSearchInputSearch input with debounced query. Shows TVDBSearchResult[] list below.
  • TVDBSearchResultRow with poster thumbnail, show title, year, network. Tap to select.
Pick Opponent /rps/pick-opponent

List of accepted friends. Tap one to confirm and send the challenge. Shows selected show at top for context.

  • FriendPickerListScrollable friend list. Each row: avatar, name, tap to select.
  • SelectedShowHeaderSmall sticky header showing your chosen show so the user remembers what they picked.
Waiting for Acceptance /rps/waiting/[matchId]

Shown to the challenger while waiting for the opponent to accept. Counts down from 30 minutes. Cancel button revokes the challenge.

  • ExpiryCountdownMM:SS countdown. Pulls expires_at from match. Turns red under 5 min.
  • WaitingAnimationSimple pulsing indicator — no heavy animations.

When Realtime fires with status = "accepted", auto-navigate to Choose screen.

Choose R/P/S /rps/choose/[matchId]

Both users land here simultaneously. Shows both shows (yours vs. opponent's). Three large buttons: Rock, Paper, Scissors. Once you tap, your choice is locked and submitted. Shows "Waiting for opponent..." after you've chosen.

  • ShowVersusCardSide-by-side layout: your show poster vs. opponent's. "VS" divider in the middle.
  • RPSPickerThree large buttons with icons (✊ ✋ ✌️). Disabled after selection. Selected button shows filled/active state.
  • OpponentStatusSmall label: "Waiting for {name}..." or "Opponent is ready!"

When Realtime fires with both choices set, auto-navigate to Result screen.

Result /rps/result/[matchId]

Animated reveal screen. Shows 3-2-1 countdown, then flips to reveal winner and winning show. Both users see this simultaneously via Realtime.

  • CountdownRevealLarge centred "3 → 2 → 1" number sequence, then fades to result.
  • RPSResultCardWinner name + "WINS!" label, winning show poster + title, both RPS choices shown side by side.
  • WatchTogetherCTA"Add to watchlist" or "Share" button. Optional — nice to have.

Design Notes

Tone

Casual, social, fun. This is a recommendation + social app — it should feel closer to Letterboxd or Spotify than a utility app. Use show poster art liberally since TVDB provides it.

Typography & Spacing

Use the system font stack. Minimum 14px body, 16–20px for titles. Generous touch targets (min 44×44pt per Apple HIG). Bottom tab bar should account for safe area insets on both iOS and Android.

RPS Screens

These are the highest-energy screens — the Choose and Result screens in particular should feel reactive and punchy. The countdown (3-2-1) before the result reveal is a key moment of delight. Keep animations short and snappy, no looping.

Loading States

Every screen that fetches data needs a skeleton loader — not a spinner. The RecommendationCard skeleton should mimic the poster + text layout. TVDB search results should show 3–4 skeleton rows while fetching.

Empty States

Every list screen (Friends Feed, RPS Home, Promotions) needs a designed empty state — a short message and a relevant CTA. No blank white screens.
